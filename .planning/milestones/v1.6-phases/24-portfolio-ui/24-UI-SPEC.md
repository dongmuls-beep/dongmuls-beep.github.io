## Spacing Scale

Same scale `compare.css` already uses (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | label-to-input gap (`.cmp-field`), arrow-to-number gap, bar-to-text gap |
| sm | 8px | button gaps, chip gaps, table cell vertical padding, list item gaps |
| md | 16px | card padding < 640px, table cell horizontal padding, form grid gap, section title bottom margin |
| lg | 24px | card padding >= 640px, vertical gap between page blocks < 640px |
| xl | 32px | vertical gap between page blocks >= 640px, desktop column gap |
| 2xl | 48px | page top padding (`padding-top: 48px`, as `.compare-page`), empty-state vertical padding |
| 3xl | 64px | not used |

Exceptions:
- Touch targets: every button, chip, input, option, summary, file control is `min-height: 44px` (and `min-width: 44px` for buttons).

- Combobox listbox `max-height: 352px` (8 options x 44px), scrolls beyond that.

## Color

No dark theme exists anywhere on the site (`style.css` has no `prefers-color-scheme` rules; `test_theme_color` requires `#e8edf5`). This page stays light-only like every other page.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` #e8edf5 + background orbs (existing `.background-gradient`) | page background |
| Secondary (30%) | `--surface` #ffffff (cards, inputs, listbox, dialog), `--surface-soft` #f5f8fd (table headers), `--surface-muted` #edf2f8 (notices, skeleton, bar track) | all cards are solid `--surface` (not glass) so text contrast is fixed |
| Accent (10%) | `--primary` #0b57d0, `--primary-soft` #e8f0ff | see reserved list |
| Destructive | `--danger` #dc2626 | see reserved list |
| Page-scoped: up | `--pf-up` #b91c1c (6.4:1 on white) | day-change value when > 0 (Korean convention red = up) |
| Page-scoped: down | `--pf-down` #1d4ed8 (6.7:1 on white) | day-change value when < 0 |
| Text | `--text` #0f172a, `--text-muted` #475569 | body / secondary text |

Accent (`--primary`) reserved for exactly:
1. Primary button background (`종목 추가` / `변경 저장`) with `#fff` text.
2. Focus rings (existing global rule).
3. Chart total line stroke and area fill (`--primary` at `fill-opacity: 0.12`), chart cursor dot.
4. Pressed period chip (`.cmp-chip[aria-pressed="true"]`: `--primary-soft` bg + 2px `--primary` border, existing).
5. Weight bar fill (track is `--surface-muted`).
6. Active combobox option background `--primary-soft` + 2px `--primary` left border.

Destructive (`--danger`) reserved for exactly:
1. Field error text (`.cmp-field-error`) and invalid input border (`[aria-invalid="true"]`).
2. Error-state message text (`.cmp-error`).
3. The `덮어쓰기` button in the overwrite dialog (bg `--danger`, text `#fff`, 4.8:1).
Row `삭제` buttons are neutral `.cmp-btn` (not red).

Contrast rules:
- Body/label text >= 4.5:1 on its actual surface. `--text-soft` (#64748b) only on `--surface` white; on `--surface-soft`/`--surface-muted` use `--text-muted`.
- Up/down is never color-only: always sign (`+`/`−`), arrow glyph, and an sr-only word (`상승`/`하락`), plus the same text in the data table.
- Weight bars are decorative (`aria-hidden="true"`); the percentage text next to each bar carries the value.
- `@media (forced-colors: active)`: chart line `stroke: CanvasText`, area fill `none`, weight bar fill `background: CanvasText`, pressed chip `outline: 2px solid Highlight`.
- Do not add `prefers-color-scheme` rules. If a site-wide dark theme lands later, this page only needs token changes because `portfolio.css` uses tokens, except the two `--pf-up/down` values.

## Components

### A1. Input form (PF-01)

`<form id="pf-form" novalidate>`; heading `h2#pf-holdings-h` 보유 종목.

| Field | Markup | Rules |
|-------|--------|-------|
| 종목 | `label[for=pf-code]` + `<input id="pf-code" class="cmp-input" type="text" role="combobox" aria-autocomplete="list" aria-expanded="false" aria-controls="pf-code-list" aria-describedby="pf-code-hint pf-code-err" autocomplete="off">` + `<ul id="pf-code-list" role="listbox" class="pf-listbox" hidden>` | See combobox behavior below. |
| 수량 | `<input id="pf-qty" class="cmp-input" type="text" inputmode="decimal" autocomplete="off" aria-describedby="pf-qty-hint pf-qty-err">` | Trim spaces. Validate with `PortfolioCalc.validateQty` (string). Comma is rejected, not converted. |
| 보유 시작일 | `<input id="pf-date" class="cmp-input" type="date" max="{todayIso}" aria-describedby="pf-date-hint pf-date-err">` | Validate with `PortfolioCalc.validateDate(value, todayIso)`. Default value: empty. |
| Submit | `<button type="submit" class="pf-btn-primary">종목 추가</button>` | In edit mode text `변경 저장` + extra `.cmp-btn` `취소` button. |

Each field: `.cmp-field` > `.cmp-label` + input + `.cmp-hint` (always visible) + `.cmp-field-error` (`id=*-err`, empty when valid). On invalid submit: set `aria-invalid="true"` on every bad field, fill its error text, focus the **first** invalid field, announce `pf_form_invalid` via `#pf-live`. Errors clear on the field's next `input` event.

`.pf-btn-primary`: `.cmp-btn` metrics (min-height 44px, padding 8px 16px, 14px/600, radius-sm) with `background: var(--primary); color: #fff; border-color: var(--primary)`. When rows reach `LIMITS.MAX_ROWS` (200): submit gets `aria-disabled="true"` (stays focusable), click shows `pf_err_rows_limit` in a form-level `.cmp-field-error`.

**Combobox behavior** (ARIA 1.2 list autocomplete, no auto-select):
- Source: `/data.json` rows; option label `{종목명} · {종목코드}`; match = case-insensitive substring of name OR prefix of `normalizeCode(input)`; max 8 options shown, data order.
- Typing opens the list (`aria-expanded="true"`). ArrowDown/ArrowUp move active option (`aria-activedescendant`, active option `aria-selected="true"`, wraps). Enter on an active option selects it (closes list, input shows label, stores code in view state; does **not** submit). Escape closes list (second Escape clears input). Tab closes list without selecting. Mouse click/tap selects.
- Option `<li role="option" id="pf-opt-{code}">`, min-height 44px, padding 8px 16px, 16px/400, code part `--text-muted`.
- No match: single `<li role="option" aria-disabled="true">` with `pf_combo_no_match`, not selectable.
- Listbox: `position: absolute; top: 100%; left: 0; right: 0; z-index: 10; max-height: 352px; overflow-y: auto; background: var(--surface); border: 1px solid var(--border-strong); border-radius: var(--radius-sm); box-shadow: var(--shadow-md)`. Parent `.pf-combo { position: relative }`.
- Acceptance on submit: if a code was selected and the input text still equals its label → that code. Else if `normalizeCode(text)` exactly equals a code in `/data.json` → that code. Else reject with `pf_err_code` (explicit inline error, PF-01). Editing the text after selecting clears the selection.

After a successful add: rows re-render, store save attempted, form resets, focus returns to `#pf-code`, announce `pf_added`. If start date is before the code's first price date (known after prices load) a `pre_listing` warning appears in the warnings card (see C3).

**Edit mode (default choice):** row `수정` button loads that row into the form, submit text → `변경 저장`, `취소` appears, the row gets `aria-current="true"` and `--primary-soft` background. Save replaces the row in place (same index); `취소` restores add mode. Both return focus to that row's `수정` button. Row delete is disabled (`aria-disabled`) for the row being edited.

### A2. Row table

`<div class="cmp-table-wrap" role="region" tabindex="0" aria-label="{pf_rows_region}">` > `<table id="pf-rows" class="cmp-table pf-rows-table">` with `<caption>` (sr-only by `.cmp-table caption`) = `pf_rows_caption`.

Columns (`<th scope="col">`): 종목 · 수량 · 보유 시작일 · 평가금액 · 관리.
- 종목 cell is `<th scope="row">` (name, then `.cmp-etf-code` code on its own line). Override sticky width: `.pf-rows-table th[scope="row"] { position: static; width: auto; min-width: 128px }`.
- 수량: the stored string as-is (no reformatting, preserves 8 decimals). 시작일: ISO `YYYY-MM-DD`. 평가금액: this row's latest value (`qty × last close`), `pf_won`; `-` while loading or when unavailable.
- 관리: two `.cmp-btn` buttons `수정`, `삭제` in a flex row (gap 8px). `aria-label` = `pf_edit_row_aria` / `pf_delete_row_aria` with `{row}` `{name}`.
- Rows keep insertion order; row number = index + 1 (matches `compute` warning `row`).
- Delete: no confirm (single row, re-addable). Remove row, save, announce `pf_deleted`. Focus moves to the next row's `삭제`, else previous row's `삭제`, else `#pf-code`.
- Empty: table hidden; holdings card shows `pf_rows_empty` (14px, `--text-muted`) under the form.

### A3. Export / import (`.pf-backup`)

Below the table, separated by `border-top: 1px solid var(--border)`, `padding-top: 16px`, `margin-top: 24px`. Sub-heading `h3` `pf_backup_title` 16px/600. One line `.cmp-hint` `pf_backup_hint`.

- `내보내기` `.cmp-btn`: downloads `etfsave-portfolio-YYYY-MM-DD.json` via `Blob` + temporary `<a download>`. Disabled (`aria-disabled="true"`, stays focusable, click announces `pf_export_empty`) when there are 0 rows. **Must serialize the rows on screen (memory)**, using the same envelope as `PortfolioStore.exportText` (`app`, `schemaVersion`, `exportedAt`, `rows`), so export still works when storage failed (that is exactly when the user needs it). Planner decides whether that is a small `exportText(rows)` option in the store or view code. Success: announce `pf_export_done`.
- `가져오기`: `<label class="cmp-btn pf-file" for="pf-import">` + `<input id="pf-import" type="file" accept=".json,application/json" class="cmp-sr-only">`. Focus ring drawn on the label via `.pf-file:focus-within { outline: 2px solid var(--primary); outline-offset: 2px }`. Input value is reset after each read so the same file can be chosen twice.
- Flow: read text → `store.importRows(text)`.
  - `ok` → rows replaced, re-render, announce + show `pf_import_done`.
  - `CONFIRM_REQUIRED` → open `#pf-confirm` (below). Also open it when storage is unavailable but memory rows exist (view-level check), so memory data is never replaced silently.
  - `INVALID_ROWS` → `#pf-import-result` shows `pf_import_invalid` + `<ul>` of up to 20 items `pf_import_row_error` (`{row}`행 · `{field}`: `{message}`), then `pf_import_more` with `{count}` if more. `row: 0` items render without the row prefix. Announce `pf_import_invalid`.
  - `PARSE_ERROR` / `FORMAT` / `TOO_LARGE` / `UNSUPPORTED_VERSION` → one message in `#pf-import-result`.
  - `STORAGE_UNAVAILABLE` / `QUOTA_EXCEEDED` from the final save → validate with `PortfolioStore.validateRows`, apply rows to memory, show storage banner.
- `#pf-import-result`: `.cmp-warning` block (no `role`; announcements go through `#pf-live` only), `margin-top: 8px`, hidden when empty, cleared on next import.

### A4. Overwrite confirm dialog

Native `<dialog id="pf-confirm" class="pf-dialog" aria-labelledby="pf-confirm-h" aria-describedby="pf-confirm-body">` opened with `showModal()` (platform focus trap, Escape, inert background).
- `h2#pf-confirm-h` (20px/600) `pf_confirm_title`; `p#pf-confirm-body` `pf_confirm_body` with `{count}` = current row count.
- Buttons right-aligned (stacked full-width < 640px), gap 8px, DOM order: `취소` (`.cmp-btn`) then `덮어쓰기` (`.pf-btn-danger`: `.cmp-btn` metrics, `background: var(--danger); color: #fff; border-color: var(--danger)`).
- Initial focus: `취소` (`autofocus`). Escape / `취소` → close, announce `pf_import_cancelled`, nothing changes. `덮어쓰기` → `importRows(text, { replace: true })`, close, handle result as above.
- On close, focus returns to the `가져오기` label's input (`#pf-import`).
- Style: `max-width: min(480px, 100% - 32px)`, padding 24px, `border: 1px solid var(--border)`, `border-radius: var(--radius-md)`, `background: var(--surface)`, `box-shadow: var(--shadow-md)`; `::backdrop { background: rgba(15, 23, 42, 0.5) }`.

### B1. Summary (`#pf-summary`, PF-02 / PF-03)

`h2` `pf_summary_title`. Then `.pf-stats` grid (1 col < 640, 3 cols >= 640, gap 16px). Each stat: `<div class="pf-stat">` with `background: var(--surface-soft); border: 1px solid var(--border); border-radius: var(--radius-sm); padding: 16px`; label `<p>` 14px/600 `--text-muted`; value `<p>` 20px/600 tabular.

| Stat | Label | Value |
|------|-------|-------|
| 합계 | `pf_stat_total` | `total[last]` → `pf_won` |
| 전일 대비 | `pf_stat_change` | `total[last] − total[last−1]`; text `▲ +12,345원 (+1.23%)` / `▼ −12,345원 (−1.23%)` / `– 0원 (0.00%)`; arrow in `<span aria-hidden="true">`, sr-only `pf_up`/`pf_down`/`pf_flat` before the number; color `--pf-up` / `--pf-down` / `--text`. Fewer than 2 dates or previous total 0 → `-` for the percent (amount still shown when 2 dates exist). |
| 기준일 | `pf_stat_asof` | `asOf` as `YYYY-MM-DD`, then 14px/400 `--text-muted` line `pf_asof_note`. |

Percent: 2 decimals, sign always shown. Money: `Intl.NumberFormat(htmlLang, { maximumFractionDigits: 0 })` on `Math.round(value)`, wrapped in `pf_won`.

**Fee line (PF-03)** — one `<p class="pf-fee-line">` under the stats, `margin-top: 16px`, 16px/400, `padding: 8px 16px; background: var(--surface-muted); border-radius: var(--radius-sm)`:
- For each code with latest value `v > 0`: fee `f` = `/data.json` `총보수` (percent units). Included only when `Number.isFinite(f)`. `cost = Σ v·f/100`, `base = Σ v` over included, weighted fee = `cost / base × 100`.
- Text `pf_fee_line`: `가중평균 총보수 {fee}% · 연간 예상 비용 약 {cost}`.
- Second sentence in the same `<p>` when `실부담비용` is available for at least one code: `pf_fee_real` `(실부담비용 기준 {fee}% · 약 {cost})`, computed the same way with its own include set.
- Any held code excluded for null fee → append `pf_fee_partial` `일부 종목 보수 정보 없음({names}) — 계산에서 제외했어요.` Never substitute 0.
- No code has a fee → `pf_fee_none` only.
- Fee format: up to 4 decimals, trailing zeros trimmed, min 2 decimals (`0.0047%`, `0.12%`).

**Weights** — `h3` 16px/600 `pf_weights_title`, `margin-top: 24px`; `<ul class="pf-weights">` (no bullets, gap 8px), one `<li>` per code (rows of the same code are merged), sorted by value desc:
- Line 1 (flex, space-between, wraps): name + `.cmp-etf-code` code | `45.2%` (1 decimal, 14px/600) · `pf_won` amount (14px/400 `--text-muted`).
- Line 2: `<div class="pf-bar" aria-hidden="true">` track 8px high, `background: var(--surface-muted)`, radius 4px; fill `<span>` `width: {pct}%`, `background: var(--primary)`, radius 4px. 0% → empty track.
- Weight = `byCode[c][last] / total[last]`; if total is 0, show `-` and no fill.

### B2. Chart (`#pf-chart`, PF-02)

`h2#pf-chart-h` `pf_chart_title`.

Period chips: `<div class="cmp-chip-group" role="group" aria-labelledby="pf-period-label">` with visible `.cmp-label#pf-period-label` `pf_period_label`. Five `<button type="button" class="cmp-chip" aria-pressed>`: `1개월` `3개월` `6개월` `1년` `전체`. Default **`전체`** (from earliest start date). Range end = `asOf`; start = `asOf` minus N calendar months; if start < first date, the range is clamped (button still enabled). Changing period re-renders chart + table, keeps focus on the chip, announces `pf_period_changed`.

SVG (`portfolio-chart.js`, patterned on `compare-chart.js`):

- Plot: 1 series = `total` only. Area under line `--primary` `fill-opacity: 0.12`; line `--primary` stroke 2.5 round joins.
