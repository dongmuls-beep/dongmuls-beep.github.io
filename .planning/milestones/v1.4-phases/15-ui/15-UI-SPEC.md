## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|

| sm | 8px | Compact spacing inside bar, chip gaps, table cell vertical padding (with md horizontal) |
| md | 16px | Default card/section padding on mobile, form field gaps, table cell horizontal padding |
| lg | 24px | Card padding on desktop, gap between form and result |

Exceptions (all touch-target driven, WCAG 2.5.5 / project rule):
- Touch targets min 44x44px: table checkbox hit area (visual box 20px, wrapped in a label with `min-width:44px; min-height:44px`), compare bar buttons, "비교하기" link, clear button, metric selector chips, copy-link button, calculator inputs (`min-height:44px`), legend toggles if interactive.
- Checkbox visual size 20px (not a multiple of 8 grid but multiple of 4). 
- Chart internal geometry follows `FEE_CHART` (height 200, pads 12/36/172) and is not part of the spacing scale.
- Mobile 320px minimum: horizontal page padding 16px (md); nothing may force page-level horizontal scroll.

### Compare bar (CMP-01, CMP-02)
- Layout: fixed bottom, full width, `z-index` below modals, above content. Left: count text "{count}개 선택됨" (+ helper "2~4개" when <2). Right: "선택 해제" (secondary) and "비교하기" (primary `<a>`).
- Hidden (`hidden` attribute, no space) when 0 selected. Visible when >=1.
- When count < 2: link has `aria-disabled="true"`, `tabindex` remains 0 (so SR users can discover), click is `preventDefault`ed, helper text "2개 이상 선택해 주세요" shown.
- When count >= 2: `href="/compare/?compare=CODE1,CODE2,..."` (codes uppercase, comma-joined, encoded not needed as chars are [0-9A-Z,]).
- 5th selection blocked: checkbox reverts to unchecked, bar shows inline message "최대 4개까지 비교할 수 있어요" (14px, `--danger` text NOT used; use `--text` on `--surface-muted` notice with "!" text prefix, plain text, no icon) for 3s, AND announced via `role="status"` live region (`aria-live="polite"`). Also other unchecked checkboxes set `aria-disabled="true"` visually dimmed (opacity .5) once 4 are selected — note: disabled must not remove focusability of already-checked ones.
- Live region `#cmp-live` (visually hidden) announces: "{name} 선택됨, 현재 {count}개", "{name} 선택 해제, 현재 {count}개", limit message, clear message.
- Mobile: bar content stacks into single row at >=320px: count (flex 1, ellipsis not allowed — wraps to 2 lines max), clear button (min 44px), compare link (min 44px, min-width 96px). Bar padding-bottom `env(safe-area-inset-bottom, 0px)`. Body gets bottom padding while bar visible (class `has-compare-bar` on `<body>` toggled by JS) so last table row and footer are never covered. Bar must not overlap the skip-link, language menu or scroll-to-top control: if a floating scroll-top button exists, Phase 16 offsets it (note for Phase 16: bottom offset = bar height + 16px).

### Selection checkbox (CMP-01)
- Inserted INSIDE `td.name-cell`, before the `.stock-link`, wrapped: `<label class="cmp-pick"><input type="checkbox" class="cmp-check" ...><span class="cmp-pick-box" aria-hidden="true"></span></label>`. Never a new column, never inside `.code-cell`. `tr.dataset.code` is the key.
- Accessible name: `aria-label="{name} 비교 선택"` (key `compare_select_label`, `{name}` interpolated).
- Idempotent: on every `etf:table-rendered`, re-scan rows, add missing checkboxes, restore checked from the Set, refresh bar. Skip rows without valid `data-code` (loading/error/empty rows) and rows whose code is "-".
- Layout: `.name-cell` becomes inline-flex row, gap sm (8px); checkbox label 44x44 hit area; on mobile card layout (existing data-label cards) checkbox stays on the name line, aligned start.

Metric table rules (CMP-03, CMP-04):
- Orientation: ETFs are COLUMNS, metrics are ROWS (`<th scope="col">` per ETF = ETF name as plain text (no link) + code below in 14px `--text-muted`; `<th scope="row">` per metric). Single `<table>`, real semantics.
- Values formatted with existing formatters if globally available, else `toFixed(2)+"%"` for fees; AUM formatted via existing `formatAUM` if present, else `toLocaleString("ko-KR")+"억"` (Assumption: AUM unit억 matches main table; executor must reuse `formatAUM`).
- Lowest per row (rows 총보수/기타비용/매매중개수수료/실부담비용 only; AUM row has NO lowest marker since lower AUM is not "better"). Candidate set excludes null/NaN via `isValidFee`. Marker: `<span class="cmp-best">최저</span>` + value weight 600; cell also gets `data-best="true"` for tests. Accessible: badge text is read in DOM order after the value; no aria-hidden.
- Each ETF column header includes a remove control? NO (out of scope; users edit via "다른 ETF 고르기" or URL). Assumption.

Mobile choice for metric table (justified): **horizontal scroll with sticky first column**, not stacked cards. Reason: the user's task is side-by-side comparison; stacked cards destroy row alignment and force mental joins across 4 cards. Implementation: wrapper `div.cmp-table-wrap` with `overflow-x:auto; -webkit-overflow-scrolling:touch`, `role="region"`, `tabindex="0"`, `aria-label="비교표 (가로로 스크롤할 수 있어요)"` (key `compare_table_region`); `th[scope=row]` sticky `left:0` with `--surface-soft` background and 1px right border; first column width 88px; ETF columns `min-width:116px` (2 ETFs = 88+232 = 320px fits at 320px viewport minus 0 outer padding: wrapper bleeds to viewport with padding 0, table inside; with 3-4 ETFs it scrolls). ETF names wrap (no ellipsis), max 3 lines. Right-edge fade hint (`background: linear-gradient` mask via `::after` on wrap, pointer-events none) shown only when scrollable. Text hint "좌우로 밀어 보세요" (no arrow glyph; canonical value is the i18n table) (key `compare_scroll_hint`, 14px, shown only under 640px when >2 ETFs).

Chart rules:
- Inline SVG built with `document.createElementNS`, no chart lib. Width from container (`FEE_CHART.width` set the same way script.js does; min 260, matches `viewBox`), height `FEE_CHART.height` (200) on mobile, 240 allowed on >=768px only if `FEE_CHART.height/top/bottom` are set consistently before every build (note globals are shared: compare-view sets them then calls builders synchronously; never assume script.js state).
- One shared Y scale: `computeFeeChartScale(all finite values across all series)`; one shared X start = earliest first-point date across series (`startDate` arg to `buildFeeLinePath`) and shared `today`, so lines are comparable.
- Grid/labels reuse `.fee-chart-grid`, `.fee-chart-label` classes (defined in style.css; compare.css only adds `.cmp-line`, `.cmp-marker`).
- Line: `fill:none; stroke-width:2.5; stroke-linejoin:round`. No area fill (overlap would obscure). Drawing order: series 1..4; last-drawn on top; end markers 10px, white 2px stroke outline for separation.
- Overlapping end labels are NOT rendered inside SVG (avoid collisions); values live in legend and text table.
- No hover-only info: tooltips not required. Tap/keyboard focus on legend items may highlight a series (`opacity .35` others) — optional enhancement; if implemented, legend items are `<button aria-pressed>` with 44px height. Default (not implementing) = legend items are static text. Assumption: static.
- Metric change: re-render synchronously, focus stays on the pressed chip, live region announces "{metric} 그래프로 바꿨어요".
- `prefers-reduced-motion`: no animation at all in this phase (nothing animates), so nothing to gate; no draw-in animation.
- Fee-history fetch failure: chart area shows error copy + retry; metric table remains.

Calculator rules:
- Inputs are `<input type="text" inputmode="numeric" autocomplete="off">` (return field `inputmode="decimal"` to allow "." and "-"). Parser: NFKC-normalize (full-width digits, full-width comma/period/minus to ASCII), strip commas, spaces, "원", "%", "년"; then `Number`; reject NaN → show field error, do not compute, keep last valid result hidden with `aria-live` message. Display: amount fields re-formatted with thousands commas on blur (not while typing, to keep caret stable).
- Values clamped via `CompareCalc.normalizeInputs`/`LIMITS` (MAX_AMOUNT 1조, years 1..50, return -99..100). If the user's value exceeds a limit, show the clamped value in the field on blur plus notice "최대 {limit}까지만 계산해요."
- URL sync: `amt`, `yrs`, `mon`, `ret` written via `history.replaceState` (debounced 300ms); only non-default values written; parsed on load with the same parser and clamping. `?compare=` is never modified by calculator.
- Result region: `role="status"` `aria-live="polite"` (announce headline only, not the whole list), `aria-atomic="true"` for the headline element.
- Amount formatting: `Math.round` to won, `toLocaleString("ko-KR")`; comma format only (no 억/만 short form; Assumption, limits i18n complexity).
- Layout: 2-column form grid at >=640px (lump/years, monthly/return), 1 column below; pair selects full-width; result card below form on all sizes.

## Accessibility & Interaction Checklist (binding)

- All new interactive elements >= 44x44px hit area; verified in `tests/compare_*_check.js` by CSS text assertions on `min-height:44px`.
- Contrast >= 4.5:1 for text, >= 3:1 for chart lines/UI borders. `--primary` on `--primary-soft` = 5.9:1 approx (passes); white on `--primary` = 6.4:1.
- Keyboard: Tab order follows DOM; checkbox toggles with Space; compare link is a real `<a>` (Enter activates); when `aria-disabled`, click and Enter are prevented. Focus is never trapped; no focus loss when the bar appears/disappears; after "선택 해제" focus moves to the first still-visible checkbox in the table (or `body` if none).
- Landmarks: compare bar is `<aside role="region" aria-label="ETF 비교 선택 바">` (key `compare_bar_label`) appended to `body` by JS, not inside `main`.
- `lang` follows site language switch; the new keys use the existing `data-i18n`/`getTranslation` mechanism; language switch must re-render bar, table, chart labels, calculator result text (listen to the existing language-change path; fallback: re-render on `storage`/custom event used by script.js — executor must verify the event name in script.js).
- sessionStorage: key `etf.compare.selection.v1`, JSON array of codes, all access in try/catch; failure falls back to in-memory Set silently (bar still works within the page).
- Selection is validated on read: `/^[0-9A-Z]{6}$/`, dedupe, cap 4.
- Security: all injected text through `escapeHtml` (or `textContent`); codes from URL are whitelisted against `data.json` before any use; no `innerHTML` with raw URL input.
- SEO/meta for `compare/index.html` draft: `<meta name="robots" content="noindex,follow">`, `<link rel="canonical" href="https://<site>/compare/">` (use the same origin string as index.html canonical), title/description from `compare_page_*`. Header/footer copied from current index.html as a DRAFT; Phase 16 aligns to post-a11y template.
- Print/desktop: max content width matches main page container; metric table and chart cards use `--surface`, `--radius-md`, `--shadow-sm`, 1px `--border`.
- Responsive breakpoints (page-scoped): <640px single column, sticky first column table; >=640px calculator 2-col form; >=1024px chart and text-alternative table side by side is NOT required (stack always).
