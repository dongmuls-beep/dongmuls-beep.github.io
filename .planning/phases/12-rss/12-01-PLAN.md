<assumptions>
- A1 (item content): title format "{name} ({code}) {총보수|기타비용} {인하|인상}" with multiple trigger fields joined by ", " in FIELD order (총보수 before 기타비용). Description is plain text, one line per valid change row for that code in that entry (trigger fields first, then 매매중개수수료, 실부담비용 as 참고), format "{field}: {before}% → {after}% ({인하|인상})", joined with "\n".
- A2 (dates): pubDate = updatedAt at 09:00 Asia/Seoul as fixed offset +09:00 (timezone(timedelta(hours=9)); no zoneinfo), formatted with email.utils.format_datetime -> e.g. "Wed, 11 Mar 2026 09:00:00 +0900". lastBuildDate = newest item's pubDate. When there are zero items, lastBuildDate is omitted (never wall clock).
- A3 (bulk guard): build_changelog already filters bulk entries, but the feed re-checks defensively: an entry is bulk if, for either BULK_CORRECTION_FIELDS field, distinct codes with a valid change in that field / total_count >= 0.5. total_count comes from len(data.json); if total_count is None or 0 the guard is skipped.
- A4 (ordering/cap): items sorted by updatedAt descending, then code ascending; FEED_ITEM_LIMIT = 50. Duplicate (code, updatedAt) across entries merge into one item.
- A5 (link): every item link and channel link = https://etfsave.life/changelog/ (resolved conflict 10). Channel title "etfsave.life 수수료 변동", description "국내 ETF 총보수·기타비용 변동 알림", language "ko".
- A6 (file format): new files are UTF-8 without BOM, LF line endings; output has XML declaration, ET.indent with two spaces, trailing newline.
- A7 (Python compat): code must run on Python 3.9+ (no match, no X | Y at runtime — use `from __future__ import annotations`, no datetime.UTC).
</assumptions>
